## 3. 2.4.4(1) 数据与设备模型

### 3.1 货位规模

```text
日均需求 Q = 150 + 40 = 190 件/天
加权在库 d = (150 × 7 + 40 × 14) / 190 = 8.47 天
基础需求 = 190 × 8.47 = 1,610 个
峰值需求 = 1,610 × 1.15 = 1,851.5 个
规划需求 = ceil(1,851.5 × 1.10) = 2,037 个
```

采用 2 巷道、每巷道 2 货架、30 列、10 层、2 深度的规划布局：

```text
2 × 2 × 30 × 10 × 2 = 2,400 个货位
```

### 3.2 库位分配

数据驱动策略按计划出库时间和入库时间排序，并对每个货位计算：

```text
score =
    0.55 × stacker_time
  + 35 × zone_mismatch
  + 8 × depth_penalty
  + batch_spread_penalty
```

经验式策略随机打乱全部货位，作为对照。两种策略都保留批次和商品追溯字段。

### 3.3 FIFO

对订单 `o`：

```text
earliest(o) = min inbound_time(b), b 属于产品匹配且可出库批次
```

数据驱动策略优先取最早的可用批次，并输出订单级 FIFO 合规率。若最早批次库存不足，可以继续取后续批次，不把正常跨批次补货误判为 FIFO 违规。

### 3.4 设备链

每个托盘任务按以下顺序执行：

```text
堆垛机 -> 提升机 -> AGV -> 自动分拣线
```

约束：

```text
stacker_start >= task_release
lift_start >= stacker_end + handoff
agv_start >= lift_end + handoff
sorter_start >= agv_end + sorter_handoff
```

同一台堆垛机、提升机、AGV、分拣线在同一时刻只能执行一项任务。模型不解决车辆之间的瞬时路径冲突，路径部分采用距离、设备占用和排队时间近似。

### 3.5 低温人员约束

每个作业任务绑定一个作业班组。如果某班组连续作业加上下一项任务会超过 120 分钟，系统在该任务前插入不少于 20 分钟的强制休息。输出包含：

- 班组编号；
- 作业开始和结束；
- 单次作业时长；
- 累计低温作业时间；
- 强制休息次数。

### 3.6 月台预约

人工模式没有提前预约，车辆按释放时间和固定偏移到达。协同模式分别保存：

- `requested_eta_min`：客户提交的预计到达；
- `eta_min`：TMS 在预约时的预测；
- `appointment_min`：确认的预约时刻；
- `actual_arrival_min`：仿真实际到达；
- `arrival_deviation_min`：实际到达减预约时刻；
- `prepare_by_min`：WMS 应完成的备货时刻。

月台开始时间同时满足：

```text
start >= actual_arrival
start >= cargo_ready
start >= dock_available
```

这样避免旧版模型中“预约时间直接等于到达时间”的循环论证。

## 4. 2.4.4(2) 代管仓模型

### 4.1 实体关系

```text
Merchant -> Category -> ManagedBatch -> Slot -> ManagedOrder
```

每一张出库任务必须保留：

- `merchant_id`；
- `category_id`；
- `batch_id`；
- `slot_id`；
- `order_id`。

### 4.2 货位分配评分

```text
score =
    travel_distance
  + zone_penalty
  + depth_penalty
  + merchant_affinity_penalty
  + category_affinity_penalty
```

周转等级 A、B、C 分别优先快取、常规、慢取区。优化策略降低双深位前阻挡，优先选择浅深度库位，并将同商家、同品类的货物放在相对集中的巷道。

### 4.3 翻箱率

当一个出库任务需要访问双深位后位，而前位仍有不同批次托盘且不参与本次任务时，记一次翻箱。翻箱率：

```text
flip_rate = flip_count / picked_pallets
```

## 5. 2.4.4(3) 仓配一体化模型

### 5.1 接口

| 接口 | 方向 | 作用 |
| --- | --- | --- |
| IF-01 | OMS 到 Master WMS | 下发订单、SKU、数量和承诺时间 |
| IF-02 | Master WMS 到 TMS | 回传备货状态和可装车时间 |
| IF-03 | 客户预约端到 TMS | 提交订单、车牌、ETA、提货量和温区 |
| IF-04 | TMS 到 Master WMS | 下发预约、备货截止时间和月台 |
| IF-05 | TMS 到客户预约端 | 确认月台或推送重排结果 |
| IF-06 | Master WCS 到 Master WMS | 回传设备任务状态 |

### 5.2 状态机

```text
CREATED -> RELEASED -> ALLOCATED -> PICKING -> STAGED
        -> APPOINTMENT_CONFIRMED -> LOADING -> DEPARTED
```

异常状态包括 `HOLD`、`REWORK`、`RESCHEDULED` 和 `CANCELLED`，对应规则详见 `SOP_2_4.md`。

### 5.3 动态月台调度

1. 预约时依据 TMS ETA、WMS 备货时间和月台占用生成初始月台。
2. 车辆到达后比较实际到达与预约偏差。
3. 偏差超过容忍范围时重新选择最早可用月台。
4. 输出初始月台、最终月台、重排标记、等待时间和迟到标记。
5. 如果货物未备齐，车辆等待时间单独记录为 `cargo_wait_min`，不把责任归到月台拥堵。

## 9. 已知边界

1. 设备速度、服务时间、货架尺寸和订单到达规律是显式假设，需要在试点现场用设备手册和 WMS 历史数据校准。
2. 模型采用资源占用和路径距离近似，没有求解多 AGV 瞬时路径冲突和设备故障。
3. 客户预约通过静态原型演示，没有真实微信登录、短信、地图或车牌识别接口。
4. 代管仓数据是合成样例，目的是证明关系模型和货位策略，不能用于判断银犁真实翻箱率。
5. 当前 2,400 货位对长在库情景不稳健。生姜 9 天、大蒜 18 天时需要 2,619 个货位，应通过库存周转、临时外仓或扩容处理。
6. 模型中的“月台等待下降”依赖客户接受预约、WMS 按时备货、TMS ETA 能够持续更新这三个条件。任何一条失效，都需要重新做异常情景实验。
7. 正式参赛材料中必须标注 AI 辅助生成内容，并保留数据来源、参数、运行命令和验证结果。
