# 银犁冷链城市配送 VRPTW 数据建模

> 第六届四川省大学生物流设计大赛案例 2.3「城市冷链配送网络优化与智能调度」的计算机部分实现。
> 对象：成都银犁冷藏物流股份有限公司 姜蒜与鲜面条两类城市配送业务。

组合选题范围：案例 2.1 经营分析与发展战略、2.3 城市冷链配送网络优化与智能调度、2.4 冷链仓储智能化管理。完整组合方案见 `INTEGRATED_PLAN_2_1_2_3_2_4.md`；本 `vrptw` 工程是其中 2.3 配送层的可运行技术底座，并为 2.4 的仓配协同预留数据接口。

## 1. 问题与目标

银犁物流的城配中心（(104.26, 30.85)）每天凌晨要向成都市及周边配送两类差异极大的产品：

- **姜蒜**：高温冷藏，低频次、大批量，温控相对宽松，可与同类同车；
- **鲜面条**：0-4C，极短保鲜期，高频次、小批量，**严禁与姜蒜混装**。

案例给出 **30 个姜蒜客户 + 30 个鲜面条客户** 的经纬度、需求量、期望/可接受时间窗、服务时长，以及车辆与成本参数。目标是在真实车队约束下，为每类产品排定车辆、路线、发车时刻，使总成本最小。

**车队（真实约束）**：4.2m 小型冷藏车 8 台 + 7.6m 中型冷藏车 2 台，共 10 台。

## 3. 数学模型

### 3.1 集合与参数

- 客户集合 $N = \{1,\dots,n\}$，配送中心 $0$；$n=30$（每类产品各自求解）
- 车辆类型 $t \in \{\text{small}, \text{medium}\}$，可用数量上限 $K_\text{small}=8$、$K_\text{medium}=2$
- 客户 $i$ 的需求 $q_i$（kg）、体积 $v_i$（按 250 kg/m³ 折算）、服务时长 $s_i$
- 距离 $d_{ij}$ 采用 Haversine 球面距离（km）
- 硬时间窗 $[a_i, b_i]$（案例“可接受时间窗”），软时间窗 $[e_i, l_i]$（案例“期望时间窗”）
- 单车最大载重 $W_t$、最大容积 $V_t$

### 3.2 决策变量

- $x_{ij}$：车辆是否从 $i$ 直接行驶到 $j$
- $y_{it}$：客户 $i$ 是否由 $t$ 型车辆服务
- 每辆车选择一条路线与一个发车时刻

### 3.3 目标函数

$$
\min \sum_{\text{routes } r} \Big[ F_{t(r)} + c_{t(r)} \cdot D_r + 8.5\,T^{drive}_r + 10\,T^{serve}_r + P_r + L_r \Big]
$$

- $F_t$：固定成本（200/400 元）
- $c_t$：单位运输成本（2.5/4.0 元·km）
- $D_r$：路线总里程；$T^{drive}_r = D_r/40$；$T^{serve}_r = \sum s_i/60$
- $P_r$：时间窗惩罚 $= \sum_i \big[5\cdot\max(0,e_i-\tau_i) + 15\cdot\max(0,\tau_i-l_i)\big]/60$
- $L_r = \sum_i value_i \times (0.008 + 0.0016)$：货损成本

### 3.4 约束

1. 每个客户恰好被服务一次；
2. 载重与容积不超过所选车型容量；
3. 服务开始时刻必须落在硬时间窗 $[a_i, b_i]$ 内；
4. **同一条路线内产品同质**：鲜面条与姜蒜不可混装（分两套子问题求解）；
5. 使用车辆数不超过 $K_\text{small}$、$K_\text{medium}$；
6. 发车时刻在装车高峰 03:00-07:00 附近取值，且整车在时间窗内完成服务。

## 4. 求解算法（`solver.py` + `fleet.py`）

1. **基线（人工排程模拟）**：按“可接受时间窗开启时刻”排序，逐单追加到现有路线，装不下则新开一条——模拟调度员顺序排程的习惯。
2. **构造**：Clarke-Wright 节约算法，按节约值合并路线，边合并边检查容量与时间窗。
3. **改进**：局部搜索，依次执行
   - 路线内 2-opt 反转
   - 车型重指派（小/中互换）
   - 客户跨线 relocate
   - 跨线 swap
   - 路线合并 merge
   - **减少中型车** `_reduce_medium`：当超过 2 台中型车时，尝试把最轻的中型线拆到 ≤1500 kg 并降级为小型车
4. **车队修复**：`assignment_cost` 在给定路线集合下求“满足 8 小 + 2 中”的最省车型指派；不可行则拒绝该候选。
5. **随机重启**：用 6 个不同随机初值重复搜索，取目标最优解。

## 5. 运行方式

```bash
python run.py        # 求解并输出 routes.csv / summary.json
python validate.py   # 独立校验：客户覆盖、容量、时间窗、车队规模
python dashboard.py  # 生成 output/dashboard.html 可视化看板
python render_map.py # 生成 output/route_map.png 与 cost_compare.png
python -m unittest -v test_model.py  # 数据质量与优化结果验收测试
```

核心求解仅使用 Python 标准库；静态图片生成需要 Pillow。

## 6. 结果

在 30+30 抽样客户上：

| 指标 | 人工排程 | 智能调度 |
| --- | --- | --- |
| 总成本 | 7344 元 | **5345 元** |
| 车辆配置 | 8 小 + 3 中 = 11 台 | **8 小 + 2 中 = 10 台** |
| 姜蒜里程 | 618.7 km | 402.0 km |
| 鲜面条里程 | 568.8 km | 343.5 km |
| 车队可行性 | 超出可用车队 1 台 | **满足** |
| 平均装载率（重量 / 体积） | 36.1% / 17.5% | **48.6% / 22.0%** |
| 准时送达率（期望窗 / 硬时间窗） | 43.3% / 100% | **48.3% / 100%** |

- 总成本下降 **1999 元 / 27.2%**；总里程由 1187.5 km 降至 745.5 km，下降 **37.2%**。
- 平均装载率由 36.1% 提升至 48.6%（体积口径 17.5% → 22.0%），准时送达率由 43.3% 提升至 48.3%，硬时间窗达成率始终保持 100%。
- **关键结论**：人工顺序排程下需要 11 台车，超过银犁可用城配车队；智能调度用满 10 台（8 小 + 2 中）即完成全部 60 个客户点配送，在满足时间窗与不可混装约束的同时实现显著降本。

## 7. 约束校验

`validate.py` 独立复核结果：

```
[baseline] cost=7344  small=8 medium=3  routes=11
   KPI: 平均装载率 36.1% (体积 17.5%), 准时送达率 43.3% (硬时间窗达成 100.0%)
   !! uses 3 medium vehicles (cap 2)
[optimised] cost=5345  small=8 medium=2  routes=10
   KPI: 平均装载率 48.6% (体积 22.0%), 准时送达率 48.3% (硬时间窗达成 100.0%)
   OK - all customers served once, capacities & windows satisfied, fleet respected
```

校验项：客户恰好服务一次、载重/容积、硬时间窗、车队规模；并输出平均装载率与准时送达率两项运营 KPI。

## 8. 假设与局限

- 体积按 250 kg/m³ 折算，实际重量约束为主要瓶颈；
- 货损按“每次交付的固定比例”建模（不随在途时长变化），该项为需求驱动、不影响路径排序；
- 两产品族独立求解后合并校验车队，未建模“同一车辆跨品类二次出车”的可能；
- 案例“可接受时间窗”作为硬约束，“期望时间窗”作为软惩罚，符合案例对早到/晚到惩罚系数的设定；
- 案例数据经掩饰处理，绝对值仅用于方案对比。
